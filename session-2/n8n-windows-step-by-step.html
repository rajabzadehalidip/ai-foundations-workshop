AI Foundations Workshop · Session 2

n8n on Windows
step by step

A beginner guide for running n8n locally and analysing one Persian news post with an AI model—without writing Python.

Classroom goal: start n8n on your own Windows laptop, paste one post, let an LLM return a structured label, and inspect the result. Do not try to build a large automation before this simple version works.

What you will do

1. Check what you need2. Install Node.js3. Start n8n locally4. Create your first workflow5. Add AI text analysis6. Add a review path7. Save, stop, and continue later

1. Before class: what you need

Windows laptop

Windows 10 or 11, internet access, and permission to install Node.js. If your work laptop blocks installs, work with a partner or use the instructor machine.

One API key per group

For the AI step, one OpenRouter key per group is enough. Keep it private. Never paste it into a shared document or screenshot.

One sample post

Open the workshop CSV file with Excel. Copy one long value from the text_fa column when the guide asks for it.

Do not use sensitive data. A local n8n server is useful for learning, but sending a text to an API sends it to that provider. Use only the supplied classroom dataset today.

2. Install Node.js once

1

Download the LTS installer

Open nodejs.org/en/download. Download the Windows LTS installer. For this n8n local-install route, use Node.js 20.19 through 24.x; do not choose the newer “Current” release just because it has a larger number.

2

Install with the default options

Open the downloaded installer. Continue with the default choices, especially the option that installs npm. When installation finishes, close every PowerShell or Command Prompt window.

3

Open a new PowerShell window

Press the Windows key, type PowerShell, and open it. Copy the two commands below, one at a time. Each should show a version number.

node --version
npm --version

✓ Success: you see two version numbers. If Windows says “not recognized”, restart the computer once and try again.

3. Start n8n on your laptop

4

Run this command in PowerShell

npx n8n

The first run downloads n8n, so wait patiently. Keep this PowerShell window open while n8n is running.

5

Open the local n8n page

When PowerShell says n8n has started, open your browser and type:

http://localhost:5678

Create the local owner account if n8n asks you to. This account stays on your own laptop.

Important: “localhost” means your own computer. Do not send this address to another student; it will only work on your laptop.

4. Make the first, no-code workflow

We will classify one post first. The visual flow will look like this:

Manual Trigger
→
Edit Fields
→
HTTP Request
→
View result
6

Create a workflow

In n8n, click Create Workflow. Click the plus button, search for Manual Trigger, and add it. This lets you run the workflow only when you click “Execute workflow”.

7

Add the text input

Click the plus button to the right of Manual Trigger. Search for Edit Fields. In the new node, click Add Field → String.

  • Field name: text
  • Value: paste one Persian post copied from the CSV’s text_fa column.

Click Test step. You should see your text under the text field.

5. Add AI text analysis with OpenRouter

This step uses the standard HTTP Request node. It looks technical only once; copy the values exactly.

8

Create a Header Auth credential

Click the plus button after Edit Fields and add an HTTP Request node. In Authentication, choose Generic Credential Type → Header Auth. Create a new credential:

  • Name: Authorization
  • Value: Bearer YOUR_OPENROUTER_KEY

Replace only YOUR_OPENROUTER_KEY with your own key. Save the credential. Do not share or export it.

9

Set the request basics

  • Method: POST
  • URL: https://openrouter.ai/api/v1/chat/completions
  • Send Headers: turn it on; add Content-Type with value application/json
  • Send Body: turn it on; choose JSON
10

Paste the AI request

For the JSON body, copy this. In n8n, switch the body field to Expression before pasting it. The final line reads the text you pasted earlier.

{{ {
  model: 'deepseek/deepseek-chat',
  temperature: 0,
  response_format: { type: 'json_object' },
  messages: [
    {
      role: 'system',
      content: 'You classify Persian news posts for a digital-market research team. Use only the post text. Choose exactly one label: REG, AI, COMP, TELCO. Return JSON with label, confidence from 0 to 1, a one-sentence rationale, a short evidence excerpt, and needs_review. Set needs_review to true if evidence is weak or two labels fit.'
    },
    {
      role: 'user',
      content: 'Classify this post:\n\n' + $json.text
    }
  ]
} }}

Click Test step. A successful answer appears inside choices → 0 → message → content.

6. Make the output useful: review, do not blindly trust

11

Read the model result

Open the result in the HTTP Request node. The model should return JSON similar to this:

{
  "label": "COMP",
  "confidence": 0.78,
  "rationale": "The post discusses platform market power.",
  "evidence": "short quotation from the post",
  "needs_review": false
}

Check the evidence manually against the original Persian post. JSON formatting does not make the answer true.

12

Optional: add a review branch

Once the first test works, add an Edit Fields node and create fields using expressions such as:

{{ JSON.parse($json.choices[0].message.content).label }}
{{ JSON.parse($json.choices[0].message.content).needs_review }}

Then add an IF node. If needs_review is true, send the item to a separate “Review” path. In a later class, that path can write to Google Sheets.

Stop here for today. The first success is one post → one structured response → one human check. Batch processing, Google Sheets, scheduling, and agents are extensions—not prerequisites.

7. Save, stop, and continue later

13

Save the workflow

Click Save in n8n and call it Policy Signal Triage. Your workflow is stored locally on the laptop.

14

Stop the local server

Return to the PowerShell window where n8n is running. Press Ctrl + C. This stops the local server.

15

Start again next time

npx n8n

Then open http://localhost:5678 again. Your saved workflow should still be there.

Troubleshooting

“node is not recognized”

Close PowerShell, open a new window, and try again. If it still fails, restart Windows and reinstall Node.js LTS.

localhost:5678 does not open

Check that the PowerShell window is still running npx n8n. Do not close it. Try a different browser.

401 or 402 API error

401 means the key is wrong or missing. 402 usually means the account has no credit for that model. Do not share the key in class chat.

Invalid JSON output

Run the same post again. If it repeats, shorten the post or add a clearer instruction: “Return JSON only, with no extra text.”

Expression looks red

Make sure the JSON body field is in Expression mode. Copy the complete expression, including the opening and closing double braces.

Do not use an agent yet

Get the four-node workflow working first. An agent is useful only when it has a clear goal and strictly limited tools.
