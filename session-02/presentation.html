Prompt engineering

A prompt is a small specification

Weak prompts leave the model to guess the task, audience, evidence standard, and output shape.

Strong prompts remove that uncertainty before the model generates anything.

Task: classify this news item
Context: Iranian digital markets
Labels: REG, AI, COMP, TELCO
Evidence rule: cite text only
Output: strict JSON
Uncertainty: say "unclear"
Prompt anatomy

Five parts that remove ambiguity

Goal

What decision, draft, classification, or transformation is needed?

Context

What should the model know about the domain, audience, and evidence?

Constraints

What must it not invent, omit, reveal, or assume?

Examples

What does a good answer look like when the category boundary is unfamiliar?

Output contract

What exact fields, length, language, and format are required?

Tests

Use counterexamples and edge cases before trusting a reusable prompt.

Prompt method 1 · zero-shot

Zero-shot: give instructions, not examples

Use zero-shot prompting when the task is familiar and the labels are easy to define. Tell the model exactly what to do, what evidence it may use, and how to format the answer.

Best first move

Start here. It is quick to write, easy to change, and creates a baseline for testing later improvements.

You are triaging a policy-news post.

Choose one label: REG, AI, COMP, or TELCO.
Use only the text provided.
If two labels fit, set needs_review to true.
Return JSON only.

Post: “The ministry published draft rules for online marketplace commissions.”
Prompt method 2 · few-shot

Few-shot: show the pattern you want copied

Add a few carefully chosen input → output examples when the category boundary, tone, or format is unfamiliar. The model infers the pattern from the current prompt.

Choose edge cases

Examples should clarify the judgments people disagree about—not repeat obvious cases.

Example
Post: “New rules for data portability were issued.”
Output: {"label":"REG","needs_review":false}

Example
Post: “A platform launched an AI fraud detector.”
Output: {"label":"AI","needs_review":false}

Now classify
Post: “The regulator opened a case on app-store fees.”
Prompt method 3 · chain-of-thought

For multi-step tasks, ask for a visible procedure

Chain-of-thought prompting can improve some multi-step reasoning tasks by having the model produce intermediate steps before its final answer.

Important caution

A plausible reasoning trace is not proof. Verify the final result with evidence, calculations, or a tool when correctness matters.

Question: Does this post raise a competition issue?

Work through this procedure:
1. Extract the conduct described.
2. Identify the affected market.
3. Name the relevant competition concern.
4. State what evidence is missing.
5. Give a one-sentence conclusion.

Keep each step to one short bullet.

Source: Wei et al. (2022), Chain-of-Thought Prompting

Prompt method 4 · rationale

Ask for evidence-grounded rationale—not hidden thoughts

A rationale is useful when it makes a result reviewable: it should point to the evidence in the text, name uncertainty, and make an alternative judgment visible.

Do not confuse explanation with truth

The model can produce a convincing explanation for a wrong answer. Treat it as an auditable claim, not a window into the model’s real reasoning.

Return JSON with:

label: one allowed label
rationale: one sentence linked to the post
evidence: a short verbatim excerpt
alternative_label: best competing label or null
needs_review: true if evidence is weak

Do not use outside knowledge.
Adaptation choices

Few-shot changes the prompt; fine-tuning changes the model

Few-shot promptingFine-tuning
What changes?Examples are placed in this request’s context.Model parameters are updated using a curated training set.
Speed to reviseImmediate: edit or replace examples.Slower: prepare data, train, evaluate, version, and redeploy.
Best useClarifying labels, format, or reasoning style.Persistent, high-volume behavior that prompting cannot reliably achieve.
RiskExamples consume context and may not generalize.Cost, overfitting, data governance, and maintenance.
Start with a zero-shot baseline, add few-shot examples, evaluate on held-out cases, and fine-tune only when a measured gap remains.
Prompt comparison

Make the output testable

Vague request

“Analyze this article for competition issues.”

Operational prompt

“Extract the named firms, policy instrument, affected market, one supporting excerpt, a label, and an uncertainty flag. Return JSON only.”

If you cannot describe what success looks like, you cannot reliably judge the model’s output.
Structured output

Prose is difficult to automate

Structured output makes a model easier to connect to a spreadsheet, database, dashboard, or automation.

It does not prove the values are correct. It makes them visible and checkable.

{
  "label": "COMP",
  "confidence": 0.78,
  "evidence": "…",
  "needs_review": false
}

Limitation case study · shift ciphers

A simple cipher reveals that fluent reasoning is not an algorithm

ROT13 is common in online forums for hiding spoilers. A shift cipher should be solved exactly by a simple procedure—yet LLM performance is uneven across shifts.

Why this happens

Autoregressive next-token prediction favors familiar outputs. Pretraining frequency, output probability, and accumulated errors in intermediate steps can all distort the result.

What the study found

  • GPT-4 showed a spike at shift 13, the most frequent shift in natural corpora, despite its many required steps.
  • Changing the probability of the expected output shifted GPT-4 accuracy from 26% to 70%.
  • Lesson: use code or a deterministic tool to verify deterministic tasks.

Source: Prabhakar, Griffiths & McCoy (2024)

Limitation case study · culture

“Human-like” outputs are not culturally neutral

Which Humans? compares LLM responses with large cross-cultural datasets. It finds their psychological responses are outliers and their cognitive-task performance most resembles WEIRD populations—Western, Educated, Industrialized, Rich, and Democratic.

Research implication

Do not ask a general model to stand in for “Iranian people,” “consumers,” or “the public.” Use real local evidence and test cultural assumptions.

One reported pattern

Performance declined as samples became more culturally distant from WEIRD societies (r = −.70).

Practical control

Use locally grounded sources, Persian test cases, diverse reviewers, and an explicit human-review step for culturally sensitive outputs.

Source: Atari et al. (2023), Which Humans?

Limitation case study · Persian ta’arof

Polite is not always culturally appropriate

Ta’arof is a Persian practice of ritual politeness: deference, modesty, indirectness, and reciprocal insistence. A direct answer can sound polite in general yet violate the social norm.

Simple scenario

Someone insists on paying a bill. A culturally appropriate response may involve polite refusal or reciprocal insistence—not simply “thank you, I accept.”

TaarofBench result

Across 450 role-play scenarios, none of five frontier LLMs exceeded 42% accuracy where ta’arof was appropriate; native Persian speakers averaged 81.8%.

Build cultural tests with native speakers. General politeness scores are not enough.

Source: Gohari Sadr et al. (2025), TaarofBench

Responsible use

Accelerate judgment—do not outsource accountability

Good first uses

  • Extract fields from known documents
  • Triage and thematic tagging
  • Draft alternatives and summaries
  • Find candidate passages for review

Do not delegate blindly

  • Legal or policy conclusions
  • Claims without accessible evidence
  • High-stakes decisions about people or firms
  • Publication without source checking

n8n prompt for the demo

Keep the model task narrow and inspectable

You are triaging a Persian news post for a competition-policy research team.

Choose exactly one label: REG, AI, COMP, or TELCO.

label, confidence (0 to 1), one-sentence rationale,

Outputs

Student task

Write a short model-comparison memo

  • Run one backend on the 25-post sample; if time permits, run all three.
  • Identify two posts where models disagree or report uncertainty.
